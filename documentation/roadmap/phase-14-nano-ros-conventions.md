# Phase 14 - modern nano-ros conventions

Status: in progress (2026-11-15). Steps 1, 2 and 4-7 done, CI green.
Steps 3 and 8-14 open.

Goal: run the port on current nano-ros main and move its layout and build
onto nano-ros's own conventions, so that `nros build <image>` builds every
image and the hand-written glue (root CMakeLists.txt, entry packages, the
sizing exports in build.sh) goes away.

Branches: the attempts land on `nano-ros`; each finished step is folded
into `nano-ros-migration` as a clean commit whose tree equals `nano-ros`
at that point. `nano-ros-migration` is the reviewable series (provision,
msgs, controller, platform, tests, CI, demo, docs, then one commit per
step of this phase).

## Where the port departs from the conventions

Sources: nano-ros book (`book/src/guide/build/organize-a-larger-workspace.md`,
`existing-cmake-or-vendor-tree.md`, `configure-an-image.md`,
`guide/platforms/zephyr-west-app.md`, `reference/system-toml.md`,
`reference/message-generation.md`, `guide/contracts/*`,
`extending/add-a-board.md`).

| topic | nano-ros convention | this port today | change | size |
|---|---|---|---|---|
| workspace root | no build file at the root; packages + a bringup; `nros build <image>` generates the entry and the build | hand-written `actuation_module/CMakeLists.txt` with a FreeRTOS branch and a Zephyr app | retire it once the steps below move its logic into packages | L |
| library code | every unit is a package | `src/autoware/*` are `.cmake` snippets pulled into controller_pkg; `common/`, `platform/` and `board_network_hook.cpp` are added by the root | autoware library package(s) and an `asi_common` support package; the Eigen patch, pthread shim and link flags move with them | L |
| component registration | `nano_ros_auto_add_library` + `nros_components_register_node` | `nano_ros_add_node(...)` (compat verb) + hand-written `NROS_COMPONENT` | switch to the pair | S |
| platform branching | a node package names no board or platform | controller_pkg sets `PLATFORM_*`, a `CONFIG_*` mirror and ARMv8-R checks | key off the generated config / board facts; ASI knobs become launch parameters | M |
| FreeRTOS entries | generated by `nros build`; a hand-owned one is `nros materialize` | three hand-written entry packages (`freertos_{posix,s32z2,an536}_entry`) | delete an536 and s32z2; keep posix only for its network-wait hook, or move the hook into `asi_common` | M |
| image domain | `[image.<id>] domain_id`, delivered as `DOMAIN_ID` in the generated entry | the hand-written an536 entry bakes domain 0; `build.sh` passes `-DNROS_DOMAIN_ID=2` for the demo (nano-ros issue 3856) | goes away with the generated entry | S |
| Zephyr road | `nros build fvp` writes the west app; or a guest west app with no bringup | a hybrid: hand-written west app + bringup via `-DNROS_IMAGE_SYSTEM_DIR` + manual Kconfig capabilities | controller images via `nros build`; the BUILD_TEST mains stay a guest west app | L |
| `CONFIG_NROS_*` in conf files | conf files hold Zephyr settings only; the image renders RMW, API, domain | `nano_ros_overlay.conf`, the tap conf and `tracing.conf` set `CONFIG_NROS_*` | drop them; state them as image keys / knobs | S |
| sizing knobs | `[image.<id>.knobs.<group>]` or board `[knobs]`; most derive (-1) | `build.sh` and `scripts/zephyr-nros-knobs.sh` export `NROS_MAX_PARAMETERS`, `NROS_PUBSUB_QOS_DEPTH`, buffer sizes, heap | move to knob rows (S32Z heap to the board package) or let the contract derive them; delete the exports, which shadow rows | M |
| contract | `launch/<stem>.contract.yaml` beside the launch file sizes pools and derives the sched-task spin period | none; `spin_period = "30ms"` stated by hand | add the contract (controller timer 33.3 Hz, topics); drop `spin_period` | M |
| messages | upstream messages via `<depend>`; own messages as rosidl packages; `nros_generate_interfaces` is deprecated | one pseudo-package calls `nros_generate_interfaces` x12; controller_pkg globs the generated dirs | rosidl packages for `visionpilot_msgs` / `safety_island_msgs`; upstream messages by `<depend>`; Trajectory bound in `nros-codegen.toml` | M |
| Zephyr S32Z board | board package = descriptor + package.xml + Kconfig + devicetree fragments | descriptor + prj.conf; overlays in `actuation_module/boards/`; `NROS_EXTRA_BOARD_PATH` exported | move overlays and the heap knob into the package | S |
| FreeRTOS port facts | `FREERTOS_PORT`, config dir and toolchain file are board facts | root picks the toolchain; `build.sh` sets `FREERTOS_PORT` | drop; an NXP-port board package if the CR52_GIC port is still needed | M |
| CI hooks | `nros configure --check`, `nros check --bringup`, `--workspace`, `nros check <board>` | `configure --check` only; CLI built with cargo by hand | add the checks; `just setup-cli` | S |
| sched tasks, Rust vs C++, retired names | - | already conform | none | - |

`nros build an536` was tried as-is: it resolves, generates and compiles,
then fails in `include/common/logger/logger.hpp` (`pthread_mutex_t`),
because the pthread shim and platform defines live in the root
CMakeLists.txt. That is the library/support-package work above.

## Step 7. Messages - done

- `src/visionpilot_msgs` and `src/safety_island_msgs` are stock rosidl
  packages (`rosidl_generate_interfaces`, `member_of_group
  rosidl_interface_packages`); their `.msg` files moved from
  `autoware_msgs/msg_local/`.
- controller_pkg's `package.xml` `<depend>`s on the eleven message packages it
  uses; `nano_ros_auto_add_library` generates them from the ROS / Autoware
  install (whole packages and their dependencies: 258 types, 123 of them
  unbounded, none of those received). The pseudo-package's twelve
  `nros_generate_interfaces()` calls, the `_gen_base` globs and the
  hand-listed `__nano_ros_cpp` links are gone. The two workspace packages are
  configured before controller_pkg, so the verb does not link them; the
  package links `visionpilot_msgs::visionpilot_msgs` and
  `safety_island_msgs::safety_island_msgs` itself.
- `msg_overrides/Trajectory.msg` is replaced by
  `"autoware_planning_msgs/Trajectory.points" = 250` in `nros-codegen.toml`.
  The type is now upstream's (unbounded on the wire), the local container
  still holds 250 points.
- The umbrella header moved to
  `controller_pkg/include/autoware/autoware_msgs/messages.hpp` and includes
  ROS-style `<pkg>/msg/<name>.hpp` headers. Three tier4_debug_msgs names use
  nano-ros's spelling (`float32stamped.hpp`), nano-ros issue 3882.
- The Zephyr test images (BUILD_TEST 1-5) generate the same set with
  `nros_find_interfaces(PACKAGE_XML src/controller_pkg/package.xml)`.
- `autoware_msgs/msg/*.idl` stay for the upstream `freertos_x5h` build, which
  this branch does not build.
